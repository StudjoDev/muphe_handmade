# 手鍊檔案與 QR 小卡作業指南

本文件定義 MUPHÉ Handmade 手鍊檔案功能的營運流程。目標是讓每一條客製手鍊都有一個可掃描的小卡 QR，顧客可查看晶種、配戴提醒、淨化保養與情境儀式；店主仍可在 Google Sheets 內保留訂單與諮詢管理資訊。

## 一、完整流程

1. 顧客在網站下單，或先填寫水晶諮詢表單。
2. Google Apps Script Web App 接收資料，寫入 Google Sheets，並寄送店主通知。
3. 店主完成手鍊設計後，在 Google Sheets 建立或補齊「手鍊檔案」資料列。
4. Apps Script 產生一組不含個資的 `查詢碼` 與 `查詢Token`。QR 小卡使用網站公開頁連結，例如：

   ```text
   https://studjodev.github.io/muphe_handmade/bracelet.html?token={查詢Token}
   ```

5. 使用公開檔案連結產生 QR code，並在小卡背面印上 `查詢碼` 作為手動輸入備援。
6. 印製小卡，掃碼驗證內容，放入手鍊包裝。
7. 若顧客要求移除資料，將 profile 狀態改為 `disabled`，並清除或隱藏公開內容。

### 手鍊檔案

新增 `手鍊檔案` 分頁，專門管理每條手鍊的公開 QR profile。此分頁不要取代 `諮詢紀錄` 或 `Orders`，避免把個資直接公開到 profile。

| 欄位 | 標題 | 建議值或格式 | 是否對外回傳 | 用途 |
|---|---|---|---|---|
| A | 建立時間 | `yyyy/MM/dd HH:mm:ss` | 否 | 建立時間 |
| B | 更新時間 | `yyyy/MM/dd HH:mm:ss` | 是 | 公開頁顯示更新時間或內部檢查 |
| C | 檔案ID | `BP-` 加 12 位亂數 | 是 | 公開檔案識別，不應含訂單或個資 |
| D | 查詢碼 | `MUPHE-ABCD-2345` | 否 | 印在小卡上，供手動輸入 |
| E | 查詢Token | UUID 亂數字串 | 否 | QR URL 使用，不可用 row number 或訂單編號 |
| F | 是否公開 | `公開`、`已公開`、`published`；未公開留空或 `draft` | 否 | 控制公開查詢，未公開一律回查無資料 |
| G | 公開顯示名稱 | 暱稱、空白或客人同意的稱呼 | 是 | 可選顯示，不填也可 |
| H | 手鍊名稱 | 手鍊名稱 | 是 | 公開頁標題 |
| I | 場景 | 職場防小人、上台發光等 | 是 | 情境分類 |
| J | 公開摘要 | 一句配戴提醒 | 是 | 公開頁主說明 |
| K | 水晶配置 | 每行一個晶種，可用 `晶種：含義` | 是 | 公開頁核心內容 |
| L | 能量主題 | 每行一個主題 | 是 | 公開頁能量焦點 |
| M | 脈輪主題 | 每行一個主題 | 是 | 公開頁能量焦點 |
| N | 設計說明 | 店主整理後的公開設計原因 | 是 | 店主小語備援 |
| O | 配戴指南 | 每行一項提醒 | 是 | 公開頁配戴指南 |
| P | 保養說明 | 每行一項提醒 | 是 | 公開頁保養指南 |
| Q | 日常儀式 | 每行一項儀式 | 是 | 公開頁儀式區塊 |
| R | 店主小語 | 簡短祝福或說明 | 是 | 公開頁店主小語 |
| S | 圖片網址 | 公開可讀的 HTTPS 圖片 URL | 是 | 公開頁照片 |
| T | 商品或公開頁網址 | 商品頁、官網或加購 URL | 是 | 公開頁行動按鈕 |
| U | 公開時間 | `yyyy/MM/dd HH:mm:ss` | 是 | 公開時間 |
| V | 內部備註 | 店主備註 | 否 | 不公開 |

建議保護 A 到 F、U 到 V 的系統欄位，只讓店主手動編輯 G 到 T 的公開內容欄位。若需要同意、印製狀態、保留期限等欄位，可另建內部作業分頁，不要混入公開 API 回傳欄位。

## 三、Apps Script 部署

1. 在 `Config.gs` 確認 `SPREADSHEET_ID` 指向同一份「水晶諮詢資料庫」。
2. 確認部署身分為「我自己」，存取權限為「所有人」。公開 profile 需要匿名顧客可讀，但資料範圍必須由程式控制。
3. Web App 需支援公開查詢 API：

   ```text
   GET /exec?action=braceletProfile&code={查詢碼}
   GET /exec?action=braceletProfile&token={查詢Token}
   ```

   GitHub Pages 的 `bracelet.html` 會使用 JSONP 讀取此 API。API 只回傳公開內容；未公開、停用與不存在的資料都回傳查無資料。

4. 在 Apps Script 編輯器可手動執行 `generateBraceletProfileCredentials()` 產生 `profileId`、`accessCode`、`accessToken`。不可使用客人姓名、電話、Email、訂單編號、試算表 row number。
5. 每次修改 Apps Script 後，都要到「部署」->「管理部署作業」-> 編輯 ->「版本」選擇「新版本」->「部署」。只儲存程式碼不會更新既有 Web App。
6. 若使用 `clasp` 部署，先在 `crystal-survey/google-apps-script` clone 既有 Apps Script 專案，確認 `.clasp.json` 內是正確 `scriptId`，再從 repo 根目錄執行：

   ```bash
   scripts/deploy-apps-script.sh AKfycby3nWx_LCW3fM5FonV_5BoOiKT6_19GR8L7D4EUqD0b_a4EekZmjwZiDzXNgjWarmgT "braceletProfile API update"
   ```

   `AKfyc...` 是 Web App deployment id；它不是 `scriptId`。缺少 `scriptId` 時不能用 CLI 部署。
7. 部署後用一筆測試 profile 驗證：
   - `是否公開 = 公開` 的 token 可在 `bracelet.html?token=...` 打開 profile。
   - 未公開、停用或不存在的 token 顯示查無資料。
   - profile 頁原始碼與畫面不含姓名、聯絡方式、生日、地址、預算、內部備註。

## 四、QR Code 產生

QR code 的內容只放公開頁 URL，例如 `bracelet.html?token=...`。不要放客人姓名、聯絡方式、訂單編號、生日、地址，亦不要使用會收集顧客行為的公開短網址服務。

建議流程：

1. 在 `手鍊檔案` 分頁確認 `是否公開` 為 `公開` 或 `已公開`，且 `bracelet.html?token=...` 可正常開啟。
2. 使用固定工具產生 QR PNG 或 SVG。可使用 Canva 內建 QR、內部設計工具、或本機 QR 產生工具；不要使用需要公開上傳客資的工具。
3. QR 尺寸建議：
   - 小卡上 QR 實際寬度至少 22mm。
   - 保留完整 quiet zone，QR 四周不要貼近文字、邊框或裁切線。
   - 印刷檔使用 300dpi 以上；深色 QR 搭配淺色底，避免低對比。
4. 產生後把 QR 圖檔放入小卡模板，並在內部作業紀錄標記為已校稿。
5. 每批列印前至少掃描第一張、最後一張、隨機一張，確認都導向正確 profile。

## 五、小卡印製與包裝

建議使用名片尺寸或接近尺寸的小卡，例如 90mm x 54mm。若印刷廠有固定模板，以印刷廠規格為準。

小卡正面建議包含：

| 區塊 | 內容 |
|---|---|
| 品牌 | MUPHÉ Handmade |
| 手鍊名稱 | `braceletName` |
| 情境 | `scene` |
| QR | 導向公開頁 URL |
| 短句 | 「掃描查看晶種、配戴提醒與保養方式」 |

小卡背面建議包含：

| 區塊 | 內容 |
|---|---|
| 晶種摘要 | 2 到 4 個主要晶種，不放完整私人諮詢內容 |
| 保養提醒 | 避免泡水、碰撞，依 `careInstructions` 摘要 |
| 聯絡方式 | 官方 IG、LINE 或網站 |

印製流程：

1. 從 `手鍊檔案` 篩選 `是否公開 = 公開` 且內容已校稿的資料列。
2. 將 `手鍊名稱`、`場景`、QR 圖檔與 `查詢碼` 放入小卡模板。
3. 確認裁切線、安全邊界、字體大小與 QR 對比。
4. 列印樣張並掃碼驗證。
5. 批量印製。
6. 每張小卡放入對應手鍊包裝前，再掃一次 QR。
7. 在內部作業紀錄標記已入包裝，必要時補上列印與包裝時間。

## 六、隱私規則

1. 最小公開原則：公開 profile 只顯示晶種、手鍊名稱、情境、配戴提醒、淨化保養與一般儀式文字。
2. 禁止公開：客人姓名、聯絡方式、生日、出生時間、地址、預算、付款狀態、出貨狀態、原始 payload、內部備註、完整私人狀態描述。
3. Token 安全：`查詢Token` 必須不可猜測，不可使用 row number、訂單編號、電話、Email、姓名拼音。
4. 試算表權限：Google Sheet 不得設為知道連結即可檢視；只有店主和必要協作者可編輯。
5. QR 服務：外部 QR 產生器最多只能看到公開 profile URL。若 profile URL 本身含個資，視為不合格。
6. 同意狀態：未取得顧客同意時，不得把 `是否公開` 設為公開狀態。
7. 停用流程：顧客要求刪除或撤回時，將 `是否公開` 改為空白或停用，移除公開頁內容，保留必要的內部交易紀錄。
8. 保留期限：`retentionUntil` 到期後檢查是否仍需保留；不需要時停用 profile，刪除不必要的個資。
9. 內容聲明：profile 的能量、脈輪、配戴提醒為生活風格建議，不替代醫療、心理、法律或財務專業建議。
